## 作品一：噜噜我们 travel 去 · 旅程记录小程序

一款微信小程序，支持**单人记录**与**双人共享**：一个人可以记录自己的旅行，也可以连接一位同行者（朋友、情侣都可以），共用同一个空间记录共同的旅程。不做攻略推荐，只解决一件事 — 把一趟旅行，从想去、准备、在路上到回来之后，完整地记下来。

**[📄 查看 / 下载作品集 PDF](lulu-travel-portfolio.pdf)**

### 产品结构

按旅程全周期设计，五个阶段互相回流：

| 阶段 | 功能 |
| --- | --- |
| 想去 | To Go List：愿望地点、期望时间、标签与意愿度 |
| 规划 | 旅游攻略：基础安排（住宿 / 出行 / 美食 / 打卡 / 其他）+ 按天行程 |
| 准备 | 必带清单：分类预置、勾选准备状态，未完成数回流旅程页提醒 |
| 记录 | 花销记账与分类统计、高光记录（文字 + 照片记下旅途瞬间） |
| 回忆 | 基于高光瞬间自动生成旅行日记初稿（可编辑、可重新生成）；首页汇总年度足迹与地图点亮 |

### 核心设计

- **空间模型先行**：数据先归属个人空间，连接同行者后升级为双人共享 — 新增、修改、断开都有明确规则
- **旅程中枢**：每趟旅程有自己的主页与状态（进行中 / 已完成），未完成事项聚合提醒
- **AI 的边界**：AI 只负责把用户记录的瞬间整理成文，出初稿；编辑与最终决定权在人
- **验证**：双账号真机交叉测试（两端一致、重复编辑、删除不复活、断开不可见），已发布体验版 v0.2.0

## 作品二：双人共享工作台 · Dual-User Shared Workbench

一款已上线运营的双人 Web 产品 — **为两个人分别定制的工作台**。

两位使用者的需求并不相同：一位要把工作、学习与创作全部装进来，另一位只需要待办和收藏。这个产品不做一套界面给两个人用，而是在同一套登录与共享框架之下，为两个人分别设计信息架构；彼此的进展随时可见，内容各自负责，交流保持轻量。

**[📄 查看 / 下载作品集 PDF](dual-workbench-portfolio.pdf)**

### 产品结构

| 侧 | 信息架构 |
| --- | --- |
| 集成侧 | 每日待办（「三省吾身」自问打卡）、求职（简历 / 岗位 / 投递 / 求职学习）、兼职、自媒体创作台、阅读及影音、AI（改稿工具与 GitHub 热点追踪） |
| 极简侧 | 只保留每日待办与学习网站收藏，配进度可视化与「完成有奖励」的动力机制 |

共享层：双身份登录与服务端会话鉴权、本人可编辑 / 对方只读、修改自动保存、弹幕留言。

### 核心设计

- **非对称定制**：共享的是账号、权限与数据框架，定制的是各自的信息架构 — 极简侧的减法和集成侧的集成，是同一种判断
- **共享的边界感**：可见建立在场感，只读守住边界，弹幕让交流不打扰 — 双人产品难的不是连通，是分寸
- **AI 嵌入真实工作流**：创作台「改稿助手」贴着稿件工作（润色、换标题、生成标签、压缩、按结构重排、去风险词），配风险自检与改动比对；AI 只能提议，用不用由作者决定
- **按真实反馈迭代**：创作台、GitHub 热点追踪、阅读收藏等板块，都是上线后从两位使用者的实际使用中长出来的
